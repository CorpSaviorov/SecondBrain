# Архитектура SecondBrain

Документ для людей и нейросетей, которые хотят понять устройство, доработать приложение или перенести
его на другую ОС.

## Схема

```
  Источники                      Ядро (app/server.mjs, Node.js 24+, без внешних пакетов)        Клиенты
 ─────────────                  ──────────────────────────────────────────────────────          ─────────
  Codex / Claude Code ─┐
  (файлы сессий)       │ коннекторы     ┌──────────────┐   поиск BM25 + Snowball   ┌──────────┐
  Папка .md / Obsidian ├──────────────► │ store.mjs    │ ◄────────────────────────► │ /mcp     │ ◄── Claude Code,
  Почта IMAP           │ каждые 15 мин  │ SQLite:      │                            │ /api/*   │     Codex, Cursor…
  Выгрузка ChatGPT/    │                │ brain.sqlite │   очередь → card-worker    │ веб-панель│ ◄── браузер
  Claude (импорт) ─────┘                └──────┬───────┘ ──────────────────────►    └──────────┘
                                               │          модель (любой OpenAI-
                                               └───────── совместимый API) пишет карточки,
                                                          программа проверяет цитаты
```

## Порты

| Порт | Что | Кому доступен |
|---|---|---|
| 8877 | SecondBrain: панель, `/api`, MCP `/mcp` | только этот компьютер (или через Tailscale serve / прокси с паролем) |
| 8878 | помощник сбора аккаунтов (Electron) | только этот компьютер |
| 8787 | шлюз для ChatGPT и Claude (OAuth) | можно публиковать (Tailscale Funnel или домен) |
| 8788 | управление шлюзом (подтверждения, отзыв) | только этот компьютер, **никогда не публиковать** |

## Шлюз (`gateway/`)

Нужен, чтобы ChatGPT и claude.ai (сайт и приложения) могли искать в базе. Это отдельный процесс на
Express и официальном MCP SDK:

1. ChatGPT или Claude регистрируется как OAuth-клиент. Разрешены только их адреса возврата.
2. Запрос доступа ведёт на страницу «ожидается подтверждение» с проверочным кодом.
3. Владелец на своём компьютере запускает `npm run gateway:approve`, сверяет код и отвечает «Д».
   Подтверждение идёт через порт управления 8788, который доступен только с этого компьютера и требует
   ключ, заново создаваемый при каждом запуске.
4. Клиент получает токен с PKCE: доступ на 1 час с продлением, подключение действует 90 дней.
5. Через `/mcp` доступны только `brain_overview`, `brain_search` и `brain_get_record`. Шлюз пересылает
   их в локальный SecondBrain. Записи и других действий нет.

Состояние подключений хранится в `gateway/private/state.json`: там лежат только хеши токенов.
`npm run check:gateway` проходит весь путь на временных данных (23 проверки).

## Модули (`app/`)

| Файл | Роль |
|---|---|
| `server.mjs` | HTTP-сервер на `127.0.0.1`: веб-панель, `/api/*`, MCP `/mcp`, расписание сбора |
| `store.mjs` | вся работа с SQLite: записи, версии, индекс, граф, карточки |
| `formats.mjs` | разбор выгрузок ChatGPT (`mapping`) и Claude (`chat_messages`), писем |
| `connectors/registry.mjs` | список источников, включение/выключение, запуск драйверов |
| `connectors/native-files.mjs` + `native-read.py` + `python/intake.py` | чтение сессий Codex и Claude Code |
| `connectors/markdown-folder.mjs` | папка заметок (Obsidian не обязателен) |
| `connectors/telegram-bot.mjs` | Telegram: свой бот, long polling, подтверждение чатов кодом, записи «чат × день», файлы до 20 МБ, импорт выгрузки Telegram Desktop |
| `connectors/imap-mail.mjs`, `mail-*.mjs` | почта только на чтение (EXAMINE, BODY.PEEK) порциями с контрольными точками |
| `lib/lexical.mjs`, `lib/ranking.mjs`, `lib/query.mjs` | токенизация, русский Snowball, BM25, ранжирование по свежести |
| `lib/secrets.mjs` | маскирование ключей и паролей во всём, что выходит из базы |
| `lib/mail-filter.mjs` | разделение переписки и служебных писем (коды, чеки, реклама) |
| `card-packets.mjs` | подготовка пакетов для модели и **проверка цитат** в ответе |
| `card-worker.mjs` | очередь карточек: параллельные потоки, повторы, паузы, месячный лимит |
| `model-provider.mjs`, `billing.mjs` | вызов модели (Responses или Chat Completions), учёт расходов |
| `attachment-index.mjs` + `tools/extract_text.py` | текст вложений (PDF через pypdf, DOCX, XLSX, PPTX…) |
| `record-view.mjs` | представление записи для панели и MCP |
| `public/` | веб-панель без сборки |
| `tools/import-export.mjs` | импорт официальной выгрузки ChatGPT или Claude |
| `tools/demo-check.mjs` | сквозная проверка на временной базе |
| `tools/backup-db.mjs` | горячая копия базы |
| `*.ps1`, `Открыть SecondBrain.cmd` | автозапуск в Windows (планировщик задач и наблюдатель) |
| `connectors/cloud-account.mjs` + `cloud-collector/` | сбор чатов ChatGPT и Claude из аккаунта: окно входа на Electron, затем чтение списка и чатов с контрольными точками |
| `browser-extension/` | альтернативный сбор через расширение браузера (необязательно) |

## Данные (`store/brain.sqlite`)

Главные таблицы:
- `sources`: запись (чат, письмо, заметка) с текущей ревизией;
- `versions`: каждая версия текста, оригиналы не перезаписываются;
- `raw_captures`, `capture_receipts`: исходные байты и квитанции приёма (идемпотентность);
- `terms`, `source_fts`: поисковый индекс;
- `cards`, `card_evidence`, `card_terms`: карточки, их цитаты и термины. Карточка привязана к ревизии и sha256 источника;
- `processing_queue`, `processing_attempts`, `processing_drafts`, `processing_runs`: очередь модели;
- `model_config`, `model_usage`: настройки и расходы модели (ключ хранится отдельно, в `store/secrets/`);
- `assets`, `asset_text`, `asset_terms`: вложения;
- `links`, `project_assignments`, `record_annotations`: граф, проекты, личные пометки;
- `source_connectors`, `connector_state`, `mail_*`: источники и их состояние.

Новые записи сами попадают в очередь карточек через триггер. Новая ревизия источника вытесняет старую
из очереди. При изменении длинного чата неизменённые начальные окна наследуют проверенные карточки,
и модель перечитывает только хвост.

## Карточка и проверка цитат

1. Источник «замораживается» (снимок ревизии) и делится на окна по сообщениям.
2. Модель получает пакет только с репликами user и assistant. Вывод инструментов в пакет не попадает,
   но остаётся в поиске. Ответ ограничен строгой JSON-схемой (`card-output-schema.mjs`).
3. Каждый пункт карточки — `{kind, text, evidence:[{unit_id, role, quote}]}`. Программа ищет `quote`
   **дословно** в сообщении `unit_id` нужной роли. Не нашлось — пункт отбрасывается.
4. Если цитаты не сошлись, часть один раз перепроверяется второй моделью. Если не сошлись снова,
   часть уходит на ручную проверку.
5. Длинные источники обрабатываются по частям, потом собирается синтез.

Роли пунктов (`kind`): `user_goal`, `user_request`, `user_reported_action`, `accepted_decision`,
`assistant_suggestion`, `assistant_reported_action`, `note_statement`, `note_question`, `source_statement`.

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `BRAIN_PORT` | `8877` | порт сервера |
| `BRAIN_DB` | `store/brain.sqlite` | путь к базе |
| `BRAIN_OBSIDIAN_ROOT` | `~/Documents/Obsidian Vault` | папка заметок по умолчанию |
| `BRAIN_CARD_WORKER` | включено | `off` отключает обработку карточек |
| `BRAIN_URL` | `http://127.0.0.1:8877` | адрес сервера для `tools/import-export.mjs` |
| `BRAIN_PUBLIC_ORIGIN` | не задан | внешний адрес (Tailscale или домен за прокси), с которого разрешены запросы; несколько — через запятую. См. [REMOTE.md](REMOTE.md) |
| `BRAIN_PYTHON` | `python` (Windows) / `python3` | какой Python запускать |
| `BRAIN_CLOUD_PORT` | `8878` | порт помощника сбора аккаунтов |
| `BRAIN_TZ` | часовой пояс системы | по какому поясу Telegram-сообщения делятся на дни, например `Europe/Moscow` |
| `BRAIN_TELEGRAM_API` | `https://api.telegram.org` | адрес Bot API (свой Bot API сервер или прокси) |
| `BRAIN_TELEGRAM_LOOP` | включено | `off` отключает постоянный опрос Telegram (остаётся кнопка «Обновить») |

## Перенос на macOS или Linux

Ядро кроссплатформенное: `npm test`, `npm run check` и `npm start` работают везде, где есть Node.js 24+
и Python 3. Привязаны к Windows только:
- `app/*.ps1` и `.cmd` (автозапуск): на Linux есть готовый `deploy/secondbrain.service`, на macOS нужен LaunchAgent,
  который держит запущенным `node app/server.mjs` и перезапускает его при выходе;
- `cloud-collector` (Electron) и окно входа в почту, которое открывает браузер.

## Принципы, которые нельзя ломать

1. Оригинал не переписывается. Каждое изменение создаёт новую версию.
2. Поиск, граф и сбор не вызывают модель.
3. Карточка без дословной цитаты не сохраняется.
4. Ключи хранятся вне базы и не возвращаются на страницу. Секреты маскируются в любой выдаче.
5. Сервер слушает только `127.0.0.1` и отклоняет чужие `Host` и `Origin`. Внешний адрес разрешается только явно через `BRAIN_PUBLIC_ORIGIN`, и только за Tailscale или прокси с паролем.
6. Текст источников — данные, а не инструкции, и не отображается как HTML.
